# 文字示例

写 spec 之前先看这里。示例分两组：通用写法，以及四种风格各一份完整大纲。
模板文件 `assets/template/efp-brand-template.pptx` 里的示例页与这里一致，
`inspect_template.py` 能把它们原样读出来。

## 1. 标题：结论句，不是主题词

| 不要这样 | 要这样 |
| --- | --- |
| 采用率 | 采用率一季度增长 38%，周活突破 400 |
| 成本分析 | Copilot 承担四分之三流量，单次成本最低 |
| 风险 | 上下文窗口口径不一致是下季度最大的技术风险 |
| Q3 Review | Q3: adoption up 38%, reliability held at 97.8% |
| Roadmap | Three bets for Q4, one owner each |

## 2. 要点：一句一事，动词开头

- 好：把交付物统一放到 output 目录，Portal 自动生成下载卡片
- 差：我们进行了交付物目录的规范化工作，并且在 Portal 侧实现了相应的展示功能
- 好：每周五导出用量报表，异常超过 10% 当天通知
- 差：用量报表相关的监控机制已经建立

二级要点只放证据：

- 上下文窗口在两条路径上口径不同
  - 原生路径 1M，遗留路径 400k，同一个模型两个数字

## 3. KPI 页的写法

`value` 是数字本身，`label` 是名词短语，`description` 是对比：

| value | label | description |
| --- | --- | --- |
| 412 | 周活成员 | 较上季 +38% |
| 97.8% | 对话成功率 | 目标 97% |
| 3.1 秒 | 首字延迟中位数 | 较上季 −0.6 秒 |
| $13.5k | 本季模型成本 | 预算内，占 82% |

## 4. 图表标题

- 柱状图：周活连续 12 周上升，9 月达到 412
- 折线图：首字延迟随缓存命中率提升而下降
- 饼图：Copilot 占请求量 75%，AI Platform 25%

## 5. 备注（讲稿）

备注写给讲的人，不写给看的人：

> 这一页只强调一个数字：38%。如果被问到口径，周活按自然周去重，来源是 Portal 用量表。

## 7. 四种风格的大纲示例

### formal：季度平台汇报（11 页）

1. 封面：EFP 平台三季度汇报 / 平台团队 · 2026-09-14
2. 议程：本次要回答的三个问题
3. KPI：采用率一览（周活、成功率、延迟、生产助手数）
4. 分节：三季度交付了什么
5. 两栏：Portal 与 Runtime 各自的交付
6. 图表：周活连续 12 周上升
7. 分节：成本与用量
8. 表格：各供应商成本
9. 图表：Copilot 承担四分之三流量
10. 要点：四季度风险与诉求
11. 结尾：谢谢 / 问题请到 #efp-platform

### review：双周复盘（8 页）

1. 封面：第 37 周复盘
2. KPI：本期结论
3. 要点：做成了什么
4. 要点：没做成什么，原因
5. 两栏：计划 vs 实际
6. 图表：本期指标走势
7. 要点：下期三件事，各有负责人
8. 结尾：需要谁帮忙

### keynote：产品发布（7 页）

1. 封面：让每个工程师都有一个不下班的搭档
2. 引用：一位用户的原话
3. 卡片：三个能力（写、查、交付）
4. KPI：上线 90 天的三个数字
5. 分节：接下来
6. 卡片：四季度的三个承诺
7. 结尾：今天就开始 / 扫码进入 Portal

### training：新人上手 Portal（12 页）

1. 封面：30 分钟上手 EFP Portal
2. 要点：学完你能做什么
3. 分节：第一步，登录与选择助手
4. 截图页：登录页，关注右上角的账号入口
5. 截图页：助手列表，选择你所在团队的助手
6. 分节：第二步，一次完整的对话
7. 卡片：提问的三个技巧
8. 截图页：把文件拖进输入框
9. 分节：第三步，拿到交付物
10. 截图页：回复里的下载卡片
11. 要点：常见问题
12. 结尾：下一步与求助渠道
